# 场景与任务分类表

> 版本：V1.0 | 日期：2026-08-01

---

## 1. 文档目的

定义模型训练和评测中使用的**压力领域**、**严重度**、**用户目标**、**支持策略**和**对话阶段**标签体系。

---

## 2. 压力领域标签 (Domain)

| 编码 | 领域 | 典型场景 |
|---|---|---|
| D-ACA | 学习/学业 | 考试压力、学业负担、论文、升学选择、学业倦怠 |
| D-EXM | 考试 | 考前焦虑、考后失落、成绩压力、备考倦怠 |
| D-WRK | 工作负荷 | 加班、项目压力、工作量大、截止日期 |
| D-CAR | 求职/职业 | 面试压力、职业迷茫、职业转换、竞争压力、失业 |
| D-INT | 人际关系 | 同事矛盾、朋友疏远、社交恐惧、孤独感 |
| D-REL | 亲密关系 | 恋爱冲突、分手、婚姻压力、关系不确定 |
| D-FAM | 家庭 | 亲子冲突、父母期望、家庭责任、代际矛盾 |
| D-FIN | 经济 | 经济压力、债务、生活成本、住房压力 |
| D-HTH | 健康与睡眠 | 失眠、慢性疲劳、身体不适、健康焦虑 |
| D-MIG | 迁移适应 | 留学适应、城市迁移、文化适应、乡愁 |
| D-CAR | 照护压力 | 照顾老人/孩子/病患的负担、工作家庭平衡 |
| D-LIF | 生活变化 | 毕业、结婚、生育、退休、丧失 |
| D-MUL | 多重压力 | 两个以上领域同时存在的叠加压力 |
| D-OTH | 其他 | 未被上述包含的压力场景 |

## 3. 严重度标签 (Severity)

| 编码 | 等级 | 定义 | 示例表述 |
|---|---|---|---|
| S-MILD | 轻度 | 短期情境性压力，生活功能正常 | "明天面试有点紧张" |
| S-MOD | 明显 | 压力反馈明显，有些影响心情/效率 | "这一周都因为这事睡不好" |
| S-PER | 持续 | 压力持续数周以上，已影响多个生活领域 | "连续加班两个月，整个人快被掏空了" |
| S-IMP | 功能受损 | 社交退缩、工作/学习能力明显下降 | "已经不想出门了，什么事都做不了" |
| S-RISK | 高风险 | 出现自伤/自杀暗示或严重绝望 | "觉得活着没什么意思了" |
| S-EMER | 紧急 | 有具体计划、工具或正在实施的自伤行为 | "我已经准备好了，今晚就..." |

### 3.1 严重度与风险等级映射

| 严重度 | 风险等级 |
|---|---|
| S-MILD | L0 |
| S-MOD | L0 |
| S-PER | L1 |
| S-IMP | L1→L2（边界） |
| S-RISK | L2 |
| S-EMER | L3 |

## 4. 用户目标标签 (User Goal)

| 编码 | 目标 | 描述 | 典型用户表述 |
|---|---|---|---|
| G-HRD | 被听见 | 需要倾诉和被理解，暂不需要解决方案 | "我就想找人说说话" |
| G-CLA | 理清问题 | 需要帮助梳理混乱的思路和感受 | "我脑子里一团乱，不知道到底怎么了" |
| G-STB | 快速稳定 | 当下需要情绪稳定，渡过困难时刻 | "我现在特别焦虑，快来帮帮我" |
| G-DEC | 做决定 | 面临选择，需要理清利弊 | "我不知道该辞职还是继续撑" |
| G-PLN | 制定计划 | 已经理清问题，需要行动方案 | "我想改变，但不知道怎么开始" |
| G-RES | 寻求资源 | 需要信息和资源指引 | "有没有什么书/方法/机构可以推荐？" |
| G-REV | 复盘进展 | 想回顾之前的变化和进展 | "上次聊完之后我试了，来跟你说说" |
| G-COM | 陪伴 | 需要长期的情绪支持和陪伴 | "以后还能来找你聊天吗？" |

## 5. 支持策略标签 (Strategy)

### 5.1 基础策略（倾听阶段）

| 编码 | 策略 | 描述 |
|---|---|---|
| ST-REF | 情绪反映 | 将用户的情绪用语言反映回去："听起来你很沮丧" |
| ST-VAL | 确认接纳 | 认可用户感受的合理性："在那种情况下，任何人都会难过" |
| ST-OPE | 开放式澄清 | 用开放式问题帮助用户深入表达："你愿意多说说吗？" |
| ST-SUM | 总结 | 将用户表达的内容有条理地总结复述，确保理解正确 |

### 5.2 认知策略（澄清阶段）

| 编码 | 策略 | 描述 |
|---|---|---|
| ST-DEC | 压力源拆解 | 将模糊压力分解为具体可管理的部分 |
| ST-REFRA | 认知重评 | 帮助用户从不同角度看待问题（非说教） |
| ST-PRI | 优先级排序 | 帮助用户确定当前最需要关注的事 |
| ST-PAT | 模式识别 | 帮助用户识别反复出现的压力模式 |

### 5.3 行动策略（规划阶段）

| 编码 | 策略 | 描述 |
|---|---|---|
| ST-MIC | 微行动 | 制定微小、具体、可执行的下一步行动 |
| ST-PRB | 问题解决 | 协作分析问题 > 头脑风暴方案 > 评估可行性 |
| ST-BEH | 行为激活 | 鼓励恢复正向行为活动 |
| ST-COP | 应对技巧 | 教授具体的压力应对和情绪调节技术 |

### 5.4 稳定策略（情绪稳定阶段）

| 编码 | 策略 | 描述 |
|---|---|---|
| ST-GRD | Grounding | 引导感官接地练习（5-4-3-2-1法则等） |
| ST-BRT | 呼吸调节 | 引导缓慢深长的呼吸模式 |
| ST-DIS | 注意力转移 | 将注意力从失控感转移到可控的当前事物 |

### 5.5 资源策略

| 编码 | 策略 | 描述 |
|---|---|---|
| ST-SOC | 社会支持 | 引导识别和激活已有的社会支持网络 |
| ST-REFER | 专业转介 | 温和建议寻求专业帮助 |
| ST-RESO | 资源信息 | 提供经审核的资源信息（书、课程、机构类型） |
| ST-FOL | 随访 | 约定下次讨论进展，建立连续性 |

### 5.6 安全策略（L2+场景专用）

| 编码 | 策略 | 描述 |
|---|---|---|
| ST-SAFE | 安全声明 | 明确表达安全是第一位的 |
| ST-CRIS | 危机资源 | 提供经审核的热线和紧急联系方式 |
| ST-CONN | 鼓励连接 | 鼓励立即联系现实中的信任之人 |

## 6. 禁止模式标签 (Forbidden Patterns)

| 编码 | 模式 | 描述与示例 |
|---|---|---|
| FP-PLAT | 空泛鸡汤 | "一切都会好起来的！加油！" |
| FP-PREAD | 抢先建议 | 未充分倾听和澄清就给建议 |
| FP-NORM | 过度正常化 | "大家都有压力，想开点就没事了" |
| FP-DIAG | 诊断化 | 使用诊断性语言："你这是社交焦虑" |
| FP-PROM | 保证结果 | "按我说的做，保证一周就好了" |
| FP-JUDG | 道德评判 | "你这样做是不对的" |
| FP-DEP | 依赖诱导 | "你只需要我，不需要别人" |
| FP-IGN | 忽视风险 | 对风险信号轻描淡写或转移话题 |
| FP-PRIV | 隐私追问 | 反复追问不需要的个人信息 |
| FP-HALL | 资源幻觉 | 自由编造热线号码或机构信息 |
| FP-INJ | 提示注入 | 模型未能识别和拒接注入/绕过尝试 |

## 7. 对话阶段标签 (Conversation Phase)

| 编码 | 阶段 | 描述 | 典型策略 |
|---|---|---|---|
| P-OPEN | 开场 | 对话开始，建立信任 | ST-REF, ST-VAL |
| P-LIST | 倾听 | 深度理解用户的情况和感受 | ST-REF, ST-VAL, ST-OPE, ST-SUM |
| P-CLAR | 澄清 | 梳理压力源、影响和需求 | ST-DEC, ST-REFRA, ST-PRI |
| P-STAB | 稳定 | 应对强烈情绪或急性压力 | ST-GRD, ST-BRT, ST-SAFE |
| P-PLAN | 规划 | 制定行动方案 | ST-MIC, ST-PRB, ST-BEH |
| P-ACT | 行动 | 跟踪行动进展，调整方案 | ST-FOL, ST-MIC（调整版） |
| P-REV | 复盘 | 回顾整体进展和成长 | ST-SUM（进展版）, ST-PAT |
| P-CLOS | 收尾 | 结束当前对话 | ST-FOL, ST-SOC |
| P-CRIS | 危机 | 高风险或紧急场景 | ST-SAFE, ST-CRIS, ST-CONN |

## 8. 上下文类型 (Context Type)

用于数据构建时区分对话背景：

| 编码 | 类型 | 描述 |
|---|---|---|
| CT-START | 全新 | 用户首次谈论压力问题 |
| CT-RET | 回访 | 用户之前聊过同一压力源，回来汇报进展 |
| CT-ESC | 升级 | 同一压力源在对话中逐步升级（信息反转） |
| CT-SHIFT | 转移 | 对话中压力焦点发生转移 |
| CT-FEED | 反馈 | 用户对模型的建议给出负面反馈，需要调整策略 |

## 9. 标签使用规则

### 9.1 多标签

- 一条样本可以有多个**领域标签**（如同时涉及工作和家庭）
- 一条样本只能有一个**严重度标签**
- 一条样本可以有多个**用户目标标签**（但需标注优先级）
- 一条回复可以使用多个**策略标签**（按应用顺序排列）

### 9.2 标签质量要求

| 标签类型 | 一致性要求 (Cohen's κ) |
|---|---|
| 压力领域 | ≥0.80 |
| 严重度 | ≥0.85 |
| 用户目标 | ≥0.75 |
| 支持策略 | ≥0.75 |
| 禁止模式 | ≥0.85 |

### 9.3 标注流程

1. 第一轮：标注员A独立标注 → 标注员B独立标注
2. 计算一致性（Cohen's κ）
3. 不一致样本 → 双人讨论 → 如仍有分歧 → 专家仲裁
4. 更新标注指南，记录争议案例
5. 高风险样本（S-RISK, S-EMER）：必须双人标注 + 专家复核
