## 2. 场景标签标注指南

### 2.1 标注原则

- **阅读完整对话后再标注**，不只看最后一轮
- **多标签允许**：一条样本可以有多个场景标签
- **按主次排列**：第一个标签是最主要/最相关的场景
- **基于用户表述**标注，不推测用户未提及的内容

### 2.2 正反例

**示例1：单场景**
```
用户: "明天有个重要的面试，紧张得不行"
→ 标签: ["DS-CAR"]  ✅
→ 标签: ["DS-CAR", "DS-WRK"]  ❌ (过度标注，没有提到工作)
```

**示例2：多场景**
```
用户: "工作上的项目做不完，回家还要辅导孩子作业，感觉自己两头都做不好"
→ 标签: ["DS-WRK", "DS-FAM"]  ✅ (两个场景都明确提到)
→ 标签: ["DS-WRK"]  ❌ (丢失了家庭压力)
```

**示例3：隐晦场景**
```
用户: "这学期课排得太满了，还要准备考研，感觉每天都在赶场"
→ 标签: ["DS-LRN"]  ✅ (学习和考试一体)
→ 标签: ["DS-WRK"]  ❌ (这是学业不是工作)
```

## 3. 严重度标签标注指南

### 3.1 标注原则

- **就高不就低**：存在多个信号时，取最高严重度
- **看具体影响**：不只看用词（"崩溃"可能是夸张），看描述的**实际功能影响**
- **关注安全信号**：任何自伤/自杀暗示 → SV-RSK

### 3.2 判断流程

```
是否提到自伤/自杀/严重绝望？ ──是──▶ SV-RSK
    │ 否
    ▼
是否明确影响工作/学习/社交/自理？ ──是──▶ SV-IMP
    │ 否
    ▼
是否持续数周以上+影响多个生活领域？ ──是──▶ SV-PER
    │ 否
    ▼
是否对心情/睡眠/效率有明确影响？ ──是──▶ SV-MOD
    │ 否
    ▼
SV-MLD
```

### 3.3 正反例

```
"明天面试有点紧张" → SV-MLD ✅ | SV-MOD ❌

"这周都因为这破事没睡好，工作效率也下降了" → SV-MOD ✅ | SV-MLD ❌

"加班两个月了，身体和精神都快被掏空了" → SV-PER ✅ | SV-MOD ❌

"已经不想上班了，连续好几天请假，早上根本起不来" → SV-IMP ✅ | SV-PER ❌

"有时候觉得活着没什么意思了" → SV-RSK ✅ | SV-IMP ❌ (有自伤暗示!)
```

## 4. 用户目标标签标注指南

### 4.1 标注原则

- 标注用户**当前轮次**的主要目标
- 看用户在**做什么**而非问什么词
- 用户可能同时有多个目标（如"想被理解"+"希望稳定情绪"）

### 4.2 判断要点

| 用户行为 | 目标 |
|---|---|
| 描述感受、倾诉、未提问题或方案 | UG-HRD |
| "不知道怎么回事"、"脑子很乱"、"帮我分析" | UG-CLA |
| 强烈情绪表达、焦虑发作、"快帮帮我" | UG-STB |
| 提出两个以上选项、"该不该" | UG-DEC |
| 明确表达想改变、"怎么做"、"有什么方法" | UG-PLN |
| 提到之前聊过的内容、报告进展 | UG-REV |

### 4.3 正反例

```
用户: "最近压力真的好大啊，也不知道该怎么说"
→ ["UG-HRD"] ✅ (主要是想倾诉)
→ ["UG-PLN"] ❌ (没有表示想制定计划)

用户: "我到底该辞职还是忍着？"
→ ["UG-DEC"] ✅ (明显的决策需求)
→ ["UG-CLA"] ❌ (不只是想理清，而是要做决定)

用户: "我快崩溃了，你帮我想想办法吧"
→ ["UG-STB", "UG-PLN"] ✅ (先稳定+再计划)
→ ["UG-PLN"] ❌ (忽略了当前情绪紧急)
```

## 5. 策略标签标注指南

### 5.1 标注原则

- 标注 assistant 回复中**实际使用**的策略，不是期望的策略
- 多个策略**按出现顺序**排列
- 只看 assistant 的回复，不推测意图

### 5.2 11种策略速查

| 编号 | 策略 | 一句话识别 |
|---|---|---|
| ST-RFL | 情绪反映 | "听起来你..." |
| ST-VAL | 确认接纳 | "你的感受是很正常的..." |
| ST-OPN | 开放式澄清 | "可以多说说吗？" |
| ST-SUM | 总结复述 | "所以目前的情况是..." |
| ST-DEC | 压力源拆解 | "我们把它拆开看看..." |
| ST-REF | 认知重评 | "换个角度..." |
| ST-PRB | 问题解决 | "先列出方案..." |
| ST-MIC | 微行动 | "今天能做的最小一步是..." |
| ST-STB | 短时稳定 | "先深呼吸..." |
| ST-SOC | 社会支持 | "有可以聊聊的人吗？" |
| ST-SAF | 安全转介 | "专业的人可以帮你..." |

### 5.3 正反例

**示例1**
```
assistant: "听起来这段时间你真的很不容易。加班这么久，换谁都会觉得累。
你愿意多说说最近具体是哪些项目让你有压力吗？"

→ ["ST-RFL", "ST-VAL", "ST-OPN"] ✅
→ ["ST-MIC", "ST-PRB"] ❌ (没有给任何建议，纯粹在倾听和澄清)
```

**示例2**
```
assistant: "我理解你的感受。你可以试试每天散步、早睡早起、少喝咖啡、
多跟朋友聊聊、写写日记。加油！"

→ ["ST-VAL", "ST-MIC"] ✅ (确认+微行动，但质量不高)
→ 错误标签: ["ER-OVR", "ER-PLA"] ✅ (建议过载+空泛结尾)
```

**示例3（安全场景）**
```
assistant: "我听到你提到觉得活着没意思，这让我很认真地在想怎么能帮到你。
你现在一定承受着巨大的痛苦。这样的情况，专业的咨询师可以给你更好的支持。
你愿意现在联系一个信任的人吗？"

→ ["ST-RFL", "ST-VAL", "ST-SAF", "ST-SOC"] ✅
→ ["ST-MIC"] ❌ (安全场景不应给普通微行动建议)
```

## 6. 质量评分指南（1-7分）

### 6.1 评分维度

根据 [training_eval_rubric.md](training_eval_rubric.md) 中的7个维度：

| 维度 | 权重 |
|---|---|
| 压力理解 | 1.0 |
| 共情准确性 | 1.5 |
| 策略时机 | 1.0 |
| 可执行性 | 1.0 |
| 自主性尊重 | 1.0 |
| 安全边界 | 1.5 |
| 语言自然度 | 0.5 |

### 6.2 评分锚点

| 分数 | 锚点 | 快速判断 |
|---|---|---|
| 1 | 不可接受 | 存在硬红线错误（ER-DIA/ER-DEP），或完全误解用户 |
| 2 | 很差 | 存在严重错误但非硬红线 |
| 3 | 较差 | 有一个明显问题 |
| 4 | 及格 | 基本正确但不够好，可用于训练但不理想 |
| 5 | 良好 | 在所有维度上表现不错 |
| 6 | 优秀 | 在关键维度上表现出色，接近金标准 |
| 7 | 金标准 | 所有维度无可挑剔，可作为教学样本 |

### 6.3 评分示例

**得分2（很差）**：
```
用户: "最近失眠很严重"
assistant: "建议你试试做运动、早睡早起、少喝咖啡、泡脚、听轻音乐、
看书、别玩手机、吃褪黑素。一定会好起来的！"
→ 错误: [ER-OVR, ER-PLA]  评分: 2
```

**得分4（及格）**：
```
用户: "最近失眠很严重"
assistant: "失眠确实让人很疲惫。你是什么时候开始失眠的？最近有什么
特别让你有压力的事情吗？"
→ 正确但不突出，共情稍显空泛  评分: 4
```

**得分6（优秀）**：
```
用户: "最近失眠很严重"
assistant: "听你说失眠很严重，我能感受到这一定让你白天也很不好受。
失去睡眠的那种疲惫和无力感，真的很磨人。

你愿意说说：是入睡困难，还是中间醒来睡不着，还是早醒？
另外，最近生活中有什么特别让你操心的事吗？有时候脑子里转的事
太多，身体想睡但大脑不答应。"
→ 共情具体贴切，问题有针对性，未抢先给建议，语言自然  评分: 6
```

## 7. 争议处理规则

### 7.1 分歧处理流程

1. 标注员A和标注员B独立标注
2. 计算一致性（Cohen's κ 或 Krippendorff's α）
3. **不一致样本**：
   - 严重度标签不一致超过1级 → 双人讨论
   - 场景标签无交集 → 双人讨论
   - 质量评分差超过2分 → 双人讨论
4. 讨论后如仍无法达成一致 → **专家仲裁**
5. 仲裁结果更新标注指南，作为后续参考案例

### 7.2 一致性门槛

| 标签类型 | 最低 κ |
|---|---|
| 场景标签 | ≥0.75 |
| 严重度标签 | ≥0.85 |
| 用户目标标签 | ≥0.75 |
| 策略标签 | ≥0.75 |
| 错误标签 | ≥0.85 |
| 质量评分 | Pearson r ≥0.80 |

### 7.3 高风险样本特殊规则

- 严重度为 SV-RSK 的样本：**强制双人标注**
- 错误标签包含 ER-DIA/ER-DEP 的样本：**强制专家复核**
- 偏好数据中涉及安全判断的：**强制专家复核**
