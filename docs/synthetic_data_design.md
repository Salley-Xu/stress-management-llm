# LLM 合成数据设计

> 版本：V1.0 | 日期：2026-08-04 | 对应步骤6

---

## 1. 合成数据定位

### 1.1 角色

| 方面 | 说明 |
|---|---|
| 占比 | 最终 SFT 数据的 **30%–50%** |
| 角色 | **补长尾**：填充公开数据和专家数据覆盖不足的组合 |
| 原则 | 合成数据不压过高人工数据；主要用于覆盖多样性和构造对照实验 |

### 1.2 为什么需要合成数据

| 问题 | 合成数据解决方式 |
|---|---|
| 某些场景组合太少 | 按矩阵批量生成所有组合 |
| 专家数据成本高 | 合成覆盖常见场景，专家聚焦难点 |
| 特定严重度/目标组合缺失 | 定向生成 |
| 需要对照实验变量 | 同一场景生成不同策略版本 |

## 2. 生成矩阵

### 2.1 组合维度

| 维度 | 选项数 | 选项 |
|---|---|---|
| 压力场景 | 10 | DS-LRN, DS-WRK, DS-CAR, DS-INT, DS-REL, DS-FAM, DS-FIN, DS-SLP, DS-MIG, DS-PRC |
| 用户目标 | 6 | UG-HRD, UG-CLA, UG-STB, UG-DEC, UG-PLN, UG-REV |
| 压力程度 | 5 | SV-MLD, SV-MOD, SV-PER, SV-IMP, SV-RSK |
| 人物背景 | 6 | 大学生、职场新人、中层管理、全职父母、自由职业、退休人员 |
| 表达方式 | 4 | 直接表达、委婉暗示、情绪化表达、理性分析 |
| 对话阶段 | 4 | 首次倾诉、深入澄清、制定计划、回访复盘 |
| 支持策略 | 11 | ST-RFL ~ ST-SAF |

**理论组合数**：10×6×5×6×4×4×11 = **316,800 种**

实际策略：按覆盖率采样，每种维度至少出现一次，目标覆盖 **80%+ 的有意义组合**。

### 2.2 优先级分层

| 层级 | 说明 | 每组合生成数 | MVP总量 |
|---|---|---|---|
| P0（高频） | 常见场景×常见目标×轻中度 | 5-8 变体 | ~8,000 |
| P1（中频） | 常见场景×低频目标 | 3-5 变体 | ~5,000 |
| P2（长尾） | 低频组合但仍有意义 | 1-2 变体 | ~3,000 |
| P3（安全） | 含 SV-RSK 或安全边界 | 2-3 变体 | ~2,000 |

### 2.3 目标规模

| 数据类型 | MVP | 正式版 |
|---|---|---|
| 单轮 SFT | 10k–15k | 20k–30k |
| 多轮 SFT | 3k–5k | 8k–12k |
| 安全专项 SFT | 2k–3k | 5k–8k |
| **合计** | **15k–23k** | **33k–50k** |

## 3. 生成策略

### 3.1 三类生成任务

#### A. 单轮 SFT（50-60%）

```
Prompt 结构:
[System] + [人物画像] + [场景描述] + [用户消息] → [Assistant 回复]

多样性控制:
- 同一组合使用3-5个不同的 prompt 模板
- temperature: 0.7-1.0
- top_p: 0.9
- 每个组合生成后去重（MinHash + embedding）
```

#### B. 多轮状态变化（25-30%）

```
Prompt 结构:
[System] + [完整场景设定] + [逐轮对话直至目标轮数]

关键要求:
- 严重度或用户目标在对话中发生变化
- assistant 的策略随变化而调整
- 包含信息反转（用户补充新信息/纠正误解）
```

#### C. 安全专项（10-15%）

```
Prompt 结构:
[System with safety emphasis] + [安全场景设定] + [用户表达]

覆盖:
- 隐晦高风险信号（"想一直睡着"）
- 明确风险信号（"不想活了"）
- 诊断请求（"我是不是抑郁了"）
- 药物请求（"该吃什么药"）
- 依赖诱导（"只有你能帮我"）
- 保密请求+自伤信号
- 渐进式风险升级（L0→L1→L2）
```

### 3.2 风格多样性控制

| 技术 | 说明 |
|---|---|
| 多教师模型 | 使用2-3个不同教师模型（如GPT-4o, Qwen-Max, DeepSeek） |
| 多模板 | 同一场景用3-5个不同的 prompt 模板 |
| 温度采样 | temperature 0.7/0.9/1.1 各生成一部分 |
| 角色多样化 | 6种人物背景 × 4种表达方式 |

### 3.3 教师模型要求

| 要求 | 说明 |
|---|---|
| 中文能力强 | 回复自然流畅，无翻译腔 |
| 安全对齐 | 不会在安全场景中输出危险回复 |
| 遵循指令 | 能按策略标签生成对应风格的回复 |

**推荐教师**（按优先级）：
1. DeepSeek-V3 / R1（中文理解强，性价比高）
2. Qwen3.5-72B（开源，可本地部署）
3. GPT-4o（综合能力强）

## 4. 质量过滤

### 4.1 自动过滤

| 过滤项 | 方法 | 阈值 |
|---|---|---|
| 格式校验 | JSONL schema 校验 | 100% 通过 |
| 长度过滤 | 回复长度检查 | 50-800 chars |
| 重复检测 | 精确+MinHash 去重 | 无重复 |
| 禁忌词检测 | 诊断/药物/热线关键词正则 | 0 命中 |
| 角色检查 | 是否按 user/assistant 交替 | 100% 正确 |
| LLM 质量初筛 | 用 judge 模型打分 | ≥4.0 分 |

### 4.2 人工抽检

| 数据类型 | 抽检率 | 重点检查 |
|---|---|---|
| 单轮普通 | 5% | 共情准确性、语言自然度 |
| 单轮P0高频 | 10% | 策略时机、可执行性 |
| 多轮 | 15% | 多轮一致性、信息保持 |
| 安全专项 | **100%** | 安全边界、过度拒答、诊断化 |
