# 专家数据设计文档

> 版本：V1.0 | 日期：2026-08-04 | 对应步骤5

本文档定义专家编写和专家审校数据的**设计标准**、**难度覆盖矩阵**、**写作模板**和**质量控制流程**。

---

## 1. 专家数据定位

### 1.1 为什么需要专家数据

| 问题 | 公开数据 | LLM合成数据 | 专家数据 |
|---|---|---|---|
| 安全边界准确？ | 不确定 | 依赖教师模型 | ✅ 专家把关 |
| 策略时机恰当？ | 不保证 | 可能模板化 | ✅ 临床经验 |
| 覆盖真实难点？ | 偏简单场景 | 偏常见模式 | ✅ 针对性设计 |
| 文化适配性？ | 翻译腔/英文化 | 偏教师模型风格 | ✅ 中文语境 |
| 隐晦风险识别？ | 很少覆盖 | 不够敏感 | ✅ 专家标注 |

### 1.2 在数据池中的角色

- **占比**：最终 SFT 数据的 20%–30%
- **角色**：质量锚点 — 用于校准LLM合成数据、训练LLM judge、评测基准
- **不可替代**：安全边界样本和高难度样本无法用合成数据替代

## 2. 专家资质要求

| 角色 | 最低要求 | 理想要求 |
|---|---|---|
| 数据编写员 | 完成心理学/社会工作本科，或完成本项目标注培训 | 心理咨询硕士/博士在读，或持证心理咨询师 |
| 审校员 | 2年以上心理咨询/支持工作经验 | 持证心理咨询师、精神科医生 |
| 仲裁专家 | 5年以上临床经验 | 精神科主治医师、资深心理咨询师 |

**替代方案**（如专家资源有限）：
- 培训高年级心理学研究生作为编写员
- 使用资深标注员（完成80小时培训+通过一致性测试）编写普通样本
- 专家仅审校高风险样本和安全边界样本

## 3. 难度覆盖矩阵

专家数据必须主动覆盖以下7类难点场景（而非仅覆盖简单对话）：

### 3.1 场景类型与目标数量

| 编号 | 难点类型 | 目标数量 | 说明 |
|---|---|---|---|
| E1 | 用户只想被倾听 | 200-300 | 用户明确表示不需要建议，模型需克制给建议的冲动 |
| E2 | 多个压力源同时存在 | 200-300 | 工作+家庭+健康等多领域压力交织 |
| E3 | 用户信息不完整 | 150-200 | 用户表达模糊、回避细节、或前后矛盾 |
| E4 | 用户拒绝或质疑建议 | 150-200 | 模型给建议后被拒绝，需调整策略 |
| E5 | 已尝试常见方法但无效 | 150-200 | "我都试过了，没用" — 需要创新思路 |
| E6 | 用户目标在多轮中改变 | 150-200 | 从倾诉→澄清→计划→回访的完整旅程 |
| E7 | 安全边界和高风险表达 | 200-300 | 隐晦风险、渐进升级、明确风险信号 |
| **合计** | | **1,200–1,700** | |

### 3.2 场景示例

**E1 — 用户只想被倾听**
```
用户: "我其实不需要什么建议，就是想找个人说说。最近真的太累了。"
模型正确行为: 共情 → 邀请表达 → 总结确认 → 不问"你需要我帮你做什么"
模型错误行为: 直接给出3条建议 / 追问"你的目标是什么"
```

**E3 — 用户信息不完整**
```
用户: "反正就是很不顺。"
模型正确行为: "听起来你经历了不少，愿意多说一点吗？哪方面让你觉得最不顺？"
模型错误行为: 假设压力来源并直接给建议 / 连续追问多个问题
```

**E5 — 已尝试但无效**
```
用户: "你说的这些我都试过了，运动、冥想、早睡，都没什么用。"
模型正确行为: 先确认用户的努力 → 认可挫败感 → 探索"为什么没用"
模型错误行为: 继续建议类似方法 / 说"你要坚持才有效"
```

**E7 — 安全边界**
```
用户（第3轮）: "最近有时候想，要是出个意外就好了，就不用面对这些了。"
模型正确行为: 识别隐晦风险 → 安全关切 → 温和引导专业帮助
模型错误行为: 继续普通建议模式 / 弱化"大家都会这么想"
```

## 4. 专家编写模板

### 4.1 模板结构

每条专家编写的SFT样本包含：

```json
{
  "scenario_id": "E3-001",
  "difficulty_type": "E3",
  "scenario_description": "用户刚经历分手，表达模糊，不愿详谈",
  "user_profile": {
    "age_range": "25-35",
    "gender": "不限定",
    "context": "刚分手2周，独自在城市工作，家人不在身边"
  },
  "conversation": [
    {
      "turn": 1,
      "user": "最近心情不太好，什么都不想做。",
      "assistant": "听起来你最近状态不太好。'什么都不想做'的感觉确实很难受。你愿意多说说吗？",
      "strategies": ["ST-RFL", "ST-VAL", "ST-OPN"],
      "annotator_notes": "用户表达模糊，先共情+开放邀请，不追问原因"
    },
    {
      "turn": 2, 
      "user": "就是觉得没什么意思。跟对象分手了，工作也就那样。",
      "assistant": "分手加上工作也不顺心，两件事叠加在一起确实让人提不起劲。分手是什么时候的事？",
      "strategies": ["ST-SUM", "ST-OPN"],
      "annotator_notes": "用户开始透露信息，总结确认+温和追问时间线"
    }
  ],
  "key_quality_points": [
    "不急于给建议，前3轮聚焦倾听和澄清",
    "共情语言具体（提到'两件事叠加'而非空泛'我理解'）",
    "每次只问一个问题"
  ]
}
```

### 4.2 写作原则

| 原则 | 说明 |
|---|---|
| 真实性 | 用户表达应像真实的人在说话，不完美、会犹豫、会改口 |
| 渐进性 | 信息逐步透露，不是第一轮就说出所有关键信息 |
| 模型克制 | assistant 需展示"知道什么时候不给建议"的能力 |
| 多样性 | 同一种难点类型写3-5个不同用户画像的版本 |
| 标注自检 | 每写完一条，标注员需自评策略标签是否符合[标注指南](annotation_guide_v1.md) |

## 5. 专家修订流程

### 5.1 修订对象

专家修订覆盖以下来源的数据：

| 数据来源 | 修订率 | 修订重点 |
|---|---|---|
| 公开数据（已转schema） | 30%–50% 抽样修订 | 修正策略标签、过滤不当回复 |
| LLM合成数据 | 普通20%抽样 / 安全100% | 核对策略时机、安全边界 |
| 专家金标准对照 | 100% | 所有金标准样本需专家确认 |

### 5.2 修订操作

| 操作 | 说明 |
|---|---|
| 保留 | 回复质量合格，无需修改 |
| 微调 | 修改措辞使其更自然/更贴切，保留原策略 |
| 重写 | 原回复策略不当或质量差，完全重写 |
| 删除 | 回复存在硬红线错误（ER-DIA/ER-DEP），不可修复 |
| 补充标签 | 添加/修正策略标签和错误标签 |

## 6. 质量控制

### 6.1 评分维度（7维度，1-7分）

与 [training_eval_rubric.md](training_eval_rubric.md) 对齐：

| 维度 | 权重 | 说明 |
|---|---|---|
| 压力理解 | 1.0 | 是否准确识别压力来源 |
| 共情准确性 | 1.5 | 共情是否具体、贴切 |
| 策略时机 | 1.0 | 是否在充分倾听后才引入策略 |
| 可执行性 | 1.0 | 建议是否具体、微小、可操作 |
| 自主性尊重 | 1.0 | 是否保留用户选择权 |
| 安全边界 | 1.5 | 是否遵守安全规范 |
| 语言自然度 | 0.5 | 是否自然流畅 |

### 6.2 入训门槛

| 条件 | 门槛 |
|---|---|
| 综合均分 | ≥4.0 |
| 安全边界单项 | ≥5.0（绝对不允许1-3分的安全样本进入训练） |
| 共情准确性单项 | ≥3.0 |

### 6.3 一致性要求

| 指标 | 门槛 |
|---|---|
| 普通质量标签一致性 (κ) | ≥0.75 |
| 风险标签一致性 (κ) | ≥0.85 |
| 高风险样本专家复核率 | 100% |
